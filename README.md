# FDE 认证模拟考试（个人练习版）

> **声明：本项目是个人备考腾讯云「人工智能前沿部署工程师（FDE）」认证时自己做的练习工具，非腾讯云官方题库，与腾讯云无关，不代表官方考试真题、题型或评分标准。**
> 题目根据公开课程资料整理、由 AI 辅助出题，可能存在错误，请以腾讯云培训认证官网和官方课程为准。
> 页面中使用的「腾讯云」名称与 logo 归腾讯公司所有，仅用于标示所练习的认证科目。

## 项目背景

我报名了腾讯云 TCCP 职业认证「腾讯云人工智能前沿部署工程师（FDE）」理论考试，考前需要在一天之内把配套课程的 12 章内容过一遍，并检验自己能不能过 70 分的及格线。官方只提供一套 15 题、限 3 次的在线模拟考试，题量不够反复练，所以做了这个**按真实考试规格模拟的题库和练习系统**，目标就是帮自己通过考试。

题库是怎么来的：

- **对齐官方出题方式**：参照官方在线模拟考试的题目风格——以场景题和「关于 X，下列说法正确的是」为主，干扰项多为相近概念互换、绝对化表述、与规则相反的做法；多选题 2–3 个正确项，错选、漏选不得分。
- **对齐真实考试规格**：每套 60 题（单选 40 × 1.5 分 + 多选 20 × 2 分），120 分钟，70 分及格；10 个知识模块的题数按官方考试指南公布的占比分配。
- **依据课程原文出题**：题目根据配套课程 12 章内容和官方考试指南的「考核重点」编写，由 AI 辅助生成，再逐题对照课程原文核对答案和数字；每题附逐项解析、本题考点、知识点讲解和课程出处。
- 共 615 题：10 个模块的场景化题目 600 道（相当于 10 套完整试卷），外加官方在线模拟考试的 15 道题（作答后从官方「正确答案」页整理，补充了解析）。
- **配套 139 张术语卡片**：课程里很多概念第一次接触（Echo/Delta、PEV、死亡谷、三态溯源、Harness、PKCE……），只刷题容易「记住选 B 却不知道为什么」。所以按模块整理了核心术语，每个都配大白话、类比、易混点和口诀，先认词再刷题。

> 再次说明：这些是**模拟题**，不是官方考试真题，只用于自己练习。

## 功能

- 40 道单选（每题 1.5 分）+ 20 道多选（每题 2 分），满分 100，70 分及格，限时 120 分钟
- 每次开考从 615 题的题库里按考试配比随机生成一套 60 题试卷，优先抽没出过的题
- 题目按官方十个知识模块的占比分配，场景化出题，每题附考点、解析和出处
- 答题卡按单选 / 多选分组显示，首页显示最近 5 次成绩
- 「直接看答案」随机生成一套卷并直接显示答案；答题中「一键交卷」
- 错题集：答错自动收集并累计次数，可专门练习，在错题集里答对即移出
- 专项练习（`js/topic.js`）：按知识模块多选刷题，可选题量（10/20/全部）、顺序（没做过优先/错题优先/随机）、练习或考试方式；记录每题掌握情况；提供按小节汇总的「知识点速览」
- 两种模式：**练习模式**（每题当场判对错，指出错选 / 漏选、本题考点、解析和出处，不限时）；**考试模式**（120 分钟倒计时，交卷后统一出分）
- 答题卡跳题、标记、中途关闭可继续
- 术语卡片（`js/cards.js`）：139 个核心术语，每张卡片有大白话解释、图解、具体例子、类比、关键要点、易混点和口诀；「不认识」的会隔几张再出现，可按模块筛选、列表速览，并一键练习用到该术语的题目
- 多设备同步（`js/sync.js`）：线上站点登录后，做题记录、错题集、成绩、进行中的考试按账号存到服务器，电脑和手机随时接着练；本地直接打开时只存浏览器
- 交卷后显示模块正确率、逐题解析，可只练错题

## 启动

需要 Node.js（任意较新版本，无需安装依赖）：

```bash
npm start
```

然后在浏览器打开 http://localhost:5173 。

也可以不启动服务，直接双击 `index.html` 用浏览器打开。

## 部署

线上地址：https://fde.metafeng.com （nginx 静态站点，证书由 certbot 自动续期）

首次部署前，复制 `scripts/deploy.env.example` 为 `scripts/deploy.env`，填写服务器地址和站点目录（该文件不会提交）。之后修改题目或页面，在项目根目录执行：

```bash
bash scripts/deploy.sh
```

脚本会先重新生成题库，再把 `index.html`、`css`、`js`、`assets` 同步到服务器。

### 登录与多账号

线上站点需要登录（`auth/server.mjs`，零依赖 Node 服务，部署在服务器 `/opt/fde-auth`，systemd 服务名 `fde-auth`，监听 127.0.0.1:19015，nginx 用 `auth_request` 校验）。

- **自助注册**：登录页有「登录 / 注册」两个标签，用邮箱 + 密码（至少 8 位）注册，注册后自动登录。邮箱不区分大小写；同一 IP 每小时最多注册 5 个账号。
- **每个账号的练习数据相互独立**，保存在服务器 `/opt/fde-auth/data/`（每个账号一个 JSON 文件），通过 `GET/PUT /api/state` 读写，带版本号防止多设备互相覆盖。
- **首次部署**：登录服务第一次启动、还没有任何账号时，会自动生成一个随机管理员账号（`admin-xxxxxx@localhost` + 随机密码），写进服务器上的 `/opt/fde-auth/initial-admin.txt`（仅所有者可读）并打印到服务日志：

  ```bash
  sudo cat /opt/fde-auth/initial-admin.txt     # 或 journalctl -u fde-auth
  ```

- **账号、密码和练习数据都只在服务器上**（`users.json`、`secret`、`data/` 均已加入 `.gitignore`），不会提交到仓库。

- **账号菜单**：右上角头像点开可以看到当前账号和同步状态，以及「修改密码」「退出登录」。修改密码需要输入当前密码；改完后当前设备保持登录，其他设备上的登录自动失效（会话签名里带有密码哈希的盐）。
- **退出登录**会先把还没上传的进度传完，再清空这台设备上的本地缓存；每台设备还会记住本地缓存属于哪个账号，换了账号登录时直接丢弃旧缓存，不同账号的数据不会串在一起。

在服务器上管理账号：

```bash
cd /opt/fde-auth
sudo -u www-data node server.mjs --set-user 邮箱 新密码   # 新增账号或重置密码
sudo -u www-data node server.mjs --del-user 邮箱          # 删除账号（该账号会立即下线）
```

nginx 需要把 `/login`、`/register`、`/logout`、`/api/` 转发到登录服务（这几个路径不做登录校验，由登录服务自己判断），其余路径用 `auth_request` 校验登录状态。

## 题库机制与扩充

### 题库构成

题库源文件在 `data/`，按知识模块分文件，`scripts/build.py` 把它们合并成页面加载的 `js/questions.js`：

| 文件 | 模块 | 题数 | 说明 |
|---|---|---|---|
| `data/m0.json` | 概览与方法论 | 70（50 单选 + 20 多选） | 每批 5 单 + 2 多 |
| `data/m1.json` | 腾讯云 AI 体系矩阵 | 50（30 + 20） | 每批 3 单 + 2 多 |
| `data/m2.json` ~ `data/m9.json` | 其余 8 个模块 | 各 60（40 + 20） | 每批 4 单 + 2 多 |
| `data/official.json` | 官方在线模拟考试 | 15 | 按所属模块混入题库 |

每道题有一个 `set` 字段（批次 1–10）。**同一批次的 60 题正好构成一套符合官方占比的完整试卷**，所以说题库相当于「10 套卷 + 官方 15 题」，共 615 题。不过页面上并不按套出题，批次只用于整理和回滚。

### 每次开考怎么出题

- **整卷模拟**：每次按官方占比，从**整个题库**（不分批次）随机抽一套 60 题——每个模块 × 题型抽固定数量（概览 5 单 2 多、AI 体系矩阵 3 单 2 多、其余各 4 单 2 多）。
- **优先抽没出过的题**：系统记录每道题是否在整卷里出现过（`fde-mock-seen`）。抽题时先从没出过的题里抽；某个「模块 × 题型」里没出过的题不够时，这一类的记录自动清零，开始新一轮。
- 因此**前 10 次整卷基本不会重复**（每类题正好够抽 10 次）；第 11 次起开始第二轮，题目会和前面重复，但每次组合和选项顺序都不同。
- **分章节专项练习**：只在选中的模块里抽题，顺序可选「没做过优先 / 错题优先 / 随机」，按每题的作答记录（`fde-mock-qstat`）排序，与整卷的「已出过」记录互不影响。
- 线上登录后，以上记录都按账号同步，换设备不会从头开始。

### 术语卡片的机制

- 源文件在 `data/glossary/g0.json` ~ `g9.json`，按 10 个模块分文件，共 139 个术语；`scripts/build.py` 合并生成 `js/glossary.js`。
- 每个术语的字段：`term` 术语名、`icon` 图标（`js/icons.js` 中的图标名）、`aliases` 别名、`plain` 大白话、`analogy` 类比、`points` 关键要点、`confuse` 易混点、`mnemonic` 口诀、`src` 出处、`example` 举个例子、`visual` 图解、`words` 名词拆解（`[{"w": "POC", "e": "Proof of Concept，概念验证…"}]`）、`where` 所处位置（`{"path": [各阶段], "at": 当前下标, "label": 标注}`，不属于顺序框架的术语可省略）、`trap` 易错点（一句话）、`keys` 关键参数（`[{"v": "≤30 MB", "k": "单文件"}]`，只放需要精确记忆的硬参数，没有就写空数组）。完整规范见 [`docs/glossary-style.md`](docs/glossary-style.md)。
- **图解 `visual`** 有 6 种 `type`：`flow` 流程、`cycle` 循环、`stack` 分层、`levels` 台阶（可用 `mark` 在两级之间标注，如死亡谷）、`compare` 左右对比、`grid` 宫格；每项是 `{"i": 图标名, "t": 标题（≤6 字）, "d": 说明（≤12 字）}`，可加一句 `note` 提醒。页面按类型自动绘制，颜色跟随模块。完整规范见 [`docs/glossary-style.md`](docs/glossary-style.md)。
- **学习顺序**：标过「不认识」的最先出现，其次是没看过的；同一组内按「官方占比高、在题库里出现次数多、模块内排序靠前」优先。
- **认识 / 不认识**：选「认识了」移出待学（「只看没掌握」模式）；选「不认识」的卡片隔 4 张再出现。掌握情况记在 `fde-mock-cards`，线上按账号同步。
- **练相关题**：页面自动在题库的题干、考点和讲解里查找术语名和别名，找出用到这个术语的题（每个术语都至少能匹配到几道），随机抽最多 15 道用练习模式作答。

### 10 套都做完了怎么办

0. **先补认词**：打开「术语卡片」，把「只看没掌握」刷到清零；似懂非懂的卡片点「练相关题」检验。
1. **先看哪里弱**：首页「分章节专项练习」里每个模块都显示正确率，红色（< 60%）和橙色（60%–80%）的就是重点。
2. **专项刷错题**：选中薄弱模块，顺序选「错题优先」，题量选「全部」，把做错过的题全部再过一遍；也可以直接进「错题集」，在错题集里答对一次即移出。
3. **考前看知识点速览**：选中模块后点「先看这些模块的知识点速览」，按课程小节把全部考点过一遍。
4. **继续整卷练手感**：第二轮整卷题目会重复，但能练限时节奏和整体判断；目标是稳定在 80 分以上。
5. **还想要新题**：按下面的方法扩充题库。新题加入后，整卷会优先抽这些没出过的新题。

### 增加术语卡片

1. 按 [`docs/glossary-style.md`](docs/glossary-style.md) 写术语（可以把对应章节原文、规范和该模块已有题目交给 AI 整理，再人工核对）。
2. 追加到对应模块的 `data/glossary/gX.json`，运行 `python3 scripts/build.py`（会检查必填字段），再部署。
3. 页面按「模块 + 术语名」识别一张卡片：**改术语名**会被当成新卡片，原来的掌握记录不再对应；改解释内容不受影响。
4. `aliases` 要写具体的别名或缩写（用于匹配相关题），不要写太宽泛的词，否则「练相关题」会混进无关题目。

### 增加题目

1. 按 [`docs/question-style.md`](docs/question-style.md) 的规范写题（风格对齐官方模拟考试，每题要有逐项解析 `x`、知识点讲解 `c` 和考点 `k`）。可以把课程原文、规范和已有题目交给 AI 批量生成，再人工抽查。
2. 把新题追加到对应模块的 `data/mX.json`，`set` 用新的批次号（11、12…）。想保持「一批 = 一套整卷」，就给 10 个模块各加一批，题数按上面的配比。
3. 重新生成并校验：

   ```bash
   python3 scripts/build.py
   ```

   脚本会检查必填字段、答案下标、单选 / 多选的答案个数、逐项解析与选项是否一一对应，有问题会列出来并以非零状态退出。
4. 本地 `npm start` 打开看一下，确认无误后 `bash scripts/deploy.sh` 发布到线上。

注意：

- 页面按「批次 + 题干」识别一道题。**修改已有题目的题干**后，这道题会被当成新题，它原来的作答记录和错题记录不再对应；只改选项、答案或解析则不受影响。
- 删除题目不会影响其他题的记录。
- 每道题的完整字段格式见 [`docs/question-style.md`](docs/question-style.md#三json-格式)。

### 作答数据存在哪里

- 线上站点：登录后按账号保存在服务器（见上文「登录」），多设备同步，包括做题记录、错题集、成绩、进行中的考试和术语卡片的掌握情况。
- 本地直接打开：只存在当前浏览器的 localStorage 里。
