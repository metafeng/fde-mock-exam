# 术语卡片编写规范

> 本项目 `data/glossary/` 下的 139 个术语就是按这份规范整理的。新增术语时照此编写。

读者：明天就要参加腾讯云 FDE 认证理论考试的考生。很多术语是第一次听说，需要在一个晚上快速「认词」——知道它是什么、和谁容易混、考试怎么考。

## 任务
为指定模块整理 **10–14 个核心术语**（概念、框架、清单名、方法名都算，例如「死亡谷」「PEV 交付闭环」「三态溯源」「Echo / Delta」「OAuth 2.1 与 PKCE」）。
挑选标准：考试最可能考、考生最可能陌生或混淆的。参考该模块的题库 JSON（看哪些概念被反复考）和课程原文。按重要性从高到低排序。

## 每个术语的字段（JSON 对象）

```json
{
  "term": "死亡谷",
  "aliases": ["L1→L2"],
  "plain": "大多数 AI 项目夭折的地方：Demo 做得很好，一接真实数据、真实权限、真实用户就推不动了。",
  "analogy": "像样板间装修得很漂亮，真住进去才发现水电没通。",
  "points": ["位置：L0–L4 成熟度框架中 L1（原型验证）→ L2（试点运行）之间", "原因：脏数据、权限打不通、一线不肯用", "穿越三动作：第一天接真实数据（100 条真数据胜过 10000 条理想数据）｜权限打通排在功能开发前｜找到真心愿意用的种子用户"],
  "confuse": "不是 L0→L1（那是把客户方案当需求的风险）；考题常把位置换成 L0→L1 或 L2→L3。",
  "mnemonic": "真数据、先权限、找种子",
  "src": "第 7 章 7.3"
}
```

- `term`：术语名，简短。
- `aliases`：其他写法或英文缩写（用于在题目里匹配相关题），没有就写 []。不要放太宽泛的词。
- `plain`：**一句大白话**（≤ 50 字），像跟完全没接触过的人解释。
- `analogy`：一个生活类比，帮助理解；实在没有合适的写 ""，不要硬凑。
- `points`：2–4 条关键要点，**必须与课程原文一致**（清单内容、顺序、数字、阈值不能错）。清单类术语要把清单完整列出。
- `confuse`：最容易和什么混、怎么区分、考题常见的干扰方式。1–2 句。
- `mnemonic`：帮助记清单/顺序的口诀，顺口、短；没有合适的写 ""。
- `src`：出处（章 + 小节）。

## 要求
- 内容只来自课程原文，不要编造。
- 不要写「课程中」「原文」。
- 输出合法 JSON 数组，追加到 `data/glossary/gX.json`（X 为模块编号 0–9），再运行 `python3 scripts/build.py` 校验。

## 图解与举个例子

### 1. `example`：举个例子（字符串）
- 2–3 句，一个**具体的工作场景**：某类客户 / 某个项目阶段 / 某个人遇到了什么，这个概念如何出现、怎么处理。
- 要有画面感（行业、人物角色、数字、动作），例如：「某银行的智能问答 Demo 用整理好的 50 条 FAQ 演示效果很好；一接真实客服工单，数据格式乱、权限申请卡了三周、坐席也不愿用——项目停在了 L1→L2 的死亡谷。」
- 例子中的规则、数字必须与课程原文一致；不要写「课程中」「原文」。

### 2. `visual`：图解（对象）
从下面 6 种类型中选**最贴切的一种**，把概念的结构画出来。文字要短：`t` ≤ 10 个字，`d` ≤ 20 个字。条目数 2–6 个。

| type | 适用 | 结构 |
|---|---|---|
| `flow` | 有先后顺序的步骤 / 阶段 | `{"type":"flow","items":[{"t":"P 原型","d":"1–2 周 · 让客户挑错"}, ...]}` |
| `cycle` | 循环往复的环节（最后回到第一步） | `{"type":"cycle","items":[{"t":"感知","d":"..."}, ...]}` |
| `stack` | 分层结构（从上到下叠放） | `{"type":"stack","items":[{"t":"数据层","d":"管进出"}, ...]}` |
| `levels` | 逐级递进的等级 / 成熟度 | `{"type":"levels","items":[{"t":"L0","d":"场景识别"}, ...],"mark":{"between":[1,2],"label":"死亡谷"}}`（`mark` 可选，标在第 between[0] 与 between[1] 项之间，下标从 0 开始） |
| `compare` | 两个概念的对比 | `{"type":"compare","left":{"t":"Echo","items":["判断该做什么","…"]},"right":{"t":"Delta","items":["把它做出来","…"]}}`（每边 2–4 条） |
| `grid` | 并列的清单（几个要素、几条规则） | `{"type":"grid","items":[{"t":"Skill","d":"怎么做"}, ...]}` |

可选字段 `"note"`：一句 ≤ 30 字的图下说明（如「顺序不能跳」「黑名单命中直接拒绝」）。

要求：
- 图解的内容（顺序、数字、名称）必须与课程原文一致，不能编造。
- 每个术语都要有 `visual`；实在不是结构化概念的，用 `grid` 列出它的 2–4 个关键要素。
