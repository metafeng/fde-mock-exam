# 出题与解析规范

扩充题库时按这份规范写题（无论手写还是让 AI 生成）。现有 615 道题就是按这份规范生成并逐题核对的。

## 一、题目风格（对齐官方模拟考试）

1. **不出现「课程中」「课程认为」「原文」等字样**，用正式考试的口吻。
2. **场景化优先**：至少一半题目放在真实工作场景里（客户现场、项目阶段、配置后台、上线评审、团队管理等），让考生判断「该怎么做 / 属于哪种情况 / 下一步是什么」。题干不要直接点出考点名称。
3. 另一类是官方常用的「关于 X，下列说法正确的是？」，难度在干扰项：
   - 把相邻概念的属性互换（如 L1/L2/L3 Demo 的「要快 / 要真 / 要对照」互换；P/E/V 阶段互换；三类护栏的检查时机互换）；
   - 绝对化表述（「一律」「越多越好」「即可」「只需」「一次完成即可」）；
   - 看似合理但与规则相反的做法（「先做最好做的场景」「开大会统一宣讲」「默认改成拒绝更安全」）；
   - 干扰项与正确项长度、语气相近，不要让正确项明显更长更完整。
4. 单选题 4 个选项、1 个正确；多选题 4 个选项（个别 5 个）、**2–3 个正确**，正确项位置分散（AB、AC、BD、ACD、BCD…），避免全对。
5. 正确答案必须能在课程原文中找到明确依据；数字、清单、顺序、阈值与原文完全一致。不确定的知识点不出。
6. 同一考点可以在不同批次重复考，但要换场景、换角度，题干和选项不能雷同。

## 二、解析要求

每道题除了题目本身，还要写三样东西：

- **`x` 逐项解析**：数组，长度与选项相同，`x[i]` 解释 `o[i]`。正确项以「正确：」开头、错误项以「错误：」开头，说明为什么对或错（错在哪、正确说法是什么），1–2 句。
  **不能出现选项字母**（A/B/C/D、「选项A」「前两项」），因为页面上选项顺序会随机打乱；需要指代其他选项时用内容指代。
- **`c` 知识点讲解**：把本题涉及的概念、清单、规则完整讲一遍，让没看过资料的人也能看懂（例如涉及「真 FDE / 半 FDE / 普通交付」就把三者定义都写出来）。3–6 句，或用「①…②…③…」列清单（页面会自动分行）。同样不能出现选项字母。
- **`k` 本题考点**：一句话概括，例如「Demo 三层次：L1 场景 Demo 要快｜L2 数据 Demo 要真｜L3 对照 Demo 要对照」。

`e` 是一句话总结（备用），`src` 写课程出处（章 + 小节，如「第 6 章 6.3」）。

## 三、JSON 格式

```json
{
  "set": 11,
  "t": "s",
  "k": "本题考点",
  "q": "题干",
  "o": ["选项一", "选项二", "选项三", "选项四"],
  "a": [3],
  "x": ["错误：……", "错误：……", "错误：……", "正确：……"],
  "c": "知识点讲解……",
  "e": "一句话总结",
  "src": "第 6 章 6.3"
}
```

- `set`：批次号。新增题用新的批次号（11、12…），便于以后按批次查找或回滚。
- `t`：`"s"` 单选，`"m"` 多选。
- `a`：正确选项在 `o` 中的下标（从 0 开始）。
- 模块由所在文件决定：`data/m0.json` ~ `data/m9.json` 依次对应 10 个知识模块（概览与方法论 → 安全治理与护栏），不需要写 `m` 字段。

## 四、让 AI 批量出题的做法

1. 把对应章节的课程原文、这份规范、以及该模块已有的题（`data/mX.json`，用于避免重复）一起交给 AI。
2. 明确数量和题型，例如「为『交付-做成且验得动』模块出第 11–12 批，每批 4 道单选 + 2 道多选」。
3. 要求 AI 逐题对照原文自查答案，输出合法 JSON 数组。
4. 追加到 `data/mX.json` 后运行 `python3 scripts/build.py` 校验；再抽查几道题的答案和解析。
